# Developer roadmap

1. **PC source boundary:** resolve rights/content review for address-bearing runtime hooks, generated guest/RSP data, ROM-specific config, and vendor modifications; identify the actual November 5 binary source state.
2. **PC reproducibility:** preserve/pin toolchain and vendor source; define a safe output-directed recipe for Splat, symbol generation, N64Recomp, both RSP outputs, and required instrumentation. Do not run the destructive current `recompile.sh` in a valuable worktree.
3. **PC usability:** after source review, focus on functional pause navigation and visually verified frontend/track issues without conflating experimental builds with the known-good checkpoint.
4. **USA/Exotica:** first resolve vehicle transform/attachment and source-data rights for a single existing mesh; do not claim complete imports without in-race evidence.
5. **3DS ARM11:** bind a repeatable source/build receipt to a visible framebuffer and determine whether the guest Start/menu transition is reachable.
6. **3DS RT64:** resolve authentic task ownership/side effects and produce a real connected frame before expanding the adapter.
7. **Vita:** tie the hardware log to exact source and executable hashes, then capture on-screen output and test input.
8. **Velocity:** perform interactive input testing before changing launcher availability; keep GBARecomp’s noncommercial terms visible.
9. **Launcher:** keep incomplete entries disabled and maintain per-game ROM/runtime contracts.

These are continuation suggestions, not promises or verified implementation plans.
